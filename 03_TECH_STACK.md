# SharkBridge — Technical Stack

**Version:** 1.0  
**Approach:** Build a reliable hackathon MVP with a small, understandable stack.

## 1. Recommended stack
- **Frontend:** React + TypeScript + Vite
- **Styling:** Tailwind CSS
- **Backend/API:** Python + FastAPI
- **Database:** Supabase PostgreSQL
- **Authentication:** Supabase Auth
- **AI:** Server-side LLM API integration
- **Matching:** Python scoring logic with explainable criteria
- **Email notifications:** Optional; add after core flow works
- **Deployment:** Vercel for frontend; compatible Python hosting for FastAPI

### Why this stack
React/Tailwind supports quick UI iteration; FastAPI keeps AI and matching logic in Python; Supabase provides hosted PostgreSQL and authentication. This is suitable for a hackathon and avoids training a custom model.

## 2. Architecture
Browser UI → FastAPI API → Supabase PostgreSQL  
FastAPI → LLM provider for summaries  
FastAPI → matching service for investor recommendations

The browser must never call the LLM provider using a secret API key. Keep all secrets in server environment variables.

## 4. Environment variables
Frontend:
- `VITE_API_BASE_URL`

Backend:
- `SUPABASE_URL`
- `SUPABASE_ANON_KEY` (only if required server-side for the chosen auth flow)
- `SUPABASE_SERVICE_ROLE_KEY` (server only; never expose to frontend)
- `LLM_API_KEY`
- `LLM_MODEL`
- `CORS_ORIGINS`

Use `.env.example` with placeholder values. Never commit real secrets.

## 5. Implementation notes
- Choose one authentication approach and implement it consistently. Validate the Supabase JWT on the backend before protected operations.
- Enforce authorization in the backend and/or database policies. Frontend role checks are only for navigation and UX.
- Use Pydantic schemas for request validation.
- Add timeouts and error handling to the LLM call.
- If the AI provider is unavailable, show a clear error or create a clearly labeled extractive fallback summary. Never pretend fallback output was generated by AI.
- Store AI summary timestamp and model/provider metadata when practical.
- Use deterministic matching rules first; do not use an LLM to invent match scores.
- Use migrations or SQL scripts for schema setup.
- Add seed data using synthetic businesses and investor profiles.

## 6. Build priority
P0: Auth, roles, profiles, funding applications, status updates, data access control.  
P1: AI summary, missing-information flags, explainable investor matching.  
P2: Email notifications, chat, entrepreneur connections.  
P3: Advanced financial analysis and integrations.

## 7. Definition of done
The app starts locally using documented commands, `.env.example` is complete, database schema is reproducible, key flows work end-to-end, and the README explains setup and demo accounts.
